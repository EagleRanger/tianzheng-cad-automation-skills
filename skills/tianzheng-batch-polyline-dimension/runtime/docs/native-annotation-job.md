# 数组式原生对象执行模块

`src/NativeAnnotationJob.cs` 来自已有实际使用的数组 job 执行代码。本公开稿只改本机目录绑定、类/命令和日志名称，不重写对象应用算法。它补充原有批量尺寸执行链，不替代所有类型的专用方法。

## 接入

模块随 `scripts/build_public_modules.py` 一起构建，公开构建映射登记命令 `CAD_ANNOTATION_RUN`。原受限 PowerShell 构建路线也保留同一映射。构建仅产出本地 DLL，不启动 CAD、不自动加载或执行。

接收方在专属执行环境显式设置 `CAD_NATIVE_JOB_DIRECTORY` 为已有的绝对目录，将自己的 `job.json` 放在其中。环境变量必须在 CAD 进程可见范围内生效；在已运行 CAD 外另开终端设变量不会追溯改变 CAD 的环境。不要为改变量擅自重启用户宿主。

job 必须包含 `document`（当前工作副本的完整路径）、`report`（新的输出路径）及 `mode`。首次可使用无写图动作的读取 job：

```json
{"document":"<当前工作副本完整路径>","report":"<本次新报告完整路径>","mode":"read"}
```

`details` 模式另提供当前 `handles` 数组，在内存展开显示子件；不把展开结果写回替代原生对象。输出已存在时跳过，不能用旧报告作为本次执行成功证据。

## 已保留的执行部分

- 当前文档身份检查、原生类型/属性/夹点及图层、文字、视口、填充信息读取。
- 同类型原生模板克隆、属性更新和逐次重读后的夹点移动。
- 明确列举对象的修改/删除、文字/多段线创建、分组克隆和视口参数应用。

这些写入仅供已有授权执行者消费自己的数据化 job；不包含原图对象、固定句柄、旧 job 或作者目标。`no_masks` 是范围较大的既有操作，不应在普通局部修改中启用。旧模板中的缺省颜色、字宽等也不是接收方工程标准。

写入模式与各数组字段应由接收 AI 逐项对照源码建立，不凭字段名猜测。`native_updates` 与 `native_positions` 可能跨事务执行，失败不能假定已自动回滚；保留保存点并核实际已改子集。源码中的 `APPLIED` 不是保存成功、全部要求通过或用户验收。模块不会自动保存图纸，保存策略以本次授权为准。

该实现调用活动 Document 及对应 COM 对象，须复用已验证的单宿主串行入口。它本身不是多文档/多宿主并发控制器，也不会自动提供隔离桌面、授权、前台切换或 SDK 版本适配。

## 布局策略源码

`src/annotation_layout_policy.py` 保留已有几何策略，包括有效内部锚点、真实半径/圆弧关系、引线及可见区域检查。几何函数涉及 Shapely；按接收方解释器安装公开依赖。原策略中仍有历史样例的分区枚举和缺省阈值，不是新图分类器或全局标准；先按当前规则明确角色与参数。最新 90°/0°/45°分支和真实内角检查应调用专项 Skill 的检查器，不把旧候选生成函数当完整排版程序。

实际原生测量、保存后态及目标视口图面需分别核实。原验证环境主要为 T20 V10 / AutoCAD 2021，公开参数化改动和离线编译不构成新环境实机验收。
