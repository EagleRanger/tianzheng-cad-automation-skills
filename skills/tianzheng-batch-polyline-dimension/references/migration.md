# CAD 执行源码迁移

v1.1.1 提供已有标注算法与执行模块的源码，供接收方 AI 对接自己的 Windows / 天正 / AutoCAD 环境。它不是软件安装程序，也不是任意图纸的一键部署器。

## 先分清需要接什么

| 内容 | 本包是否提供 | 接收方要做的事 |
| --- | --- | --- |
| 直线/圆弧提取、原生标注生成、排布、文字锚点与异常处理 | 提供现有公式、Python、AutoLISP、PowerShell、C# 源码 | 复用实现，不重新发明算法；按本机软件版本构建和加载 |
| 精确文档绑定、受限子进程与后台控制 | 提供已有代码和构建材料 | 绑定本次真实进程、文档、图纸副本和对象范围 |
| AutoCAD、天正、解释器与商业 SDK | 不打包第三方软件/许可 | 由接收方合法取得并配置本机路径；可公开下载的依赖自行安装 |
| 本次图纸、选择范围、文件哈希、授权和运行状态 | 不复制作者数据 | 从接收方当前任务生成真实输入，不拿旧的 READY / PASS 代替 |

`runtime/` 内的说明、源码清单与构建清单是实际入口。保留整个目录，不能只安装说明文件。参考区里保留的原控制链用于理解与对接，未声明为默认可调用入口的候选不能直接当作已验收命令。

## 对接顺序

1. 先读本 Skill、`project-contract.md` 与 runtime 自带说明；运行本 Skill 的 `scripts/inspect_capability.ps1 -AsJson` 检查清单。该检查不启动 CAD，不代表运行成功。
2. 检查本机天正 / AutoCAD 版本、Python、PowerShell 与 .NET 构建环境。解释器路径使用实际安装位置或运行时支持的环境参数，不保留作者电脑路径。
3. 按 runtime 的模块构建清单编译自有源码；CAD 托管引用来自接收方本机合法安装。不能把旧机器 DLL 哈希当作新构建的身份，也不能直接取消哈希校验。受控助手必须以本次可信构建产物与清单绑定。
4. 为本次隔离图纸副本生成真实输入：完整路径与哈希、所属进程/文档、对象 handle、ROAD / SHORE 分组、参数和明确范围。原控制链若使用任务登记/交接结构，应按同一输入结构生成本机数据，或仅适配宿主入口并保留等价安全检查。
5. 首次只读检查与预览通过后，在获得授权的副本上运行已有逻辑。检查原生对象类型、端点关联、尺寸含义、排布与文字位置；保存与独立重开只在相应授权内执行。

安装、构建、入口适配与新机验证是迁移工作；要求接收方从文字说明重写我们已有的几何与标注算法不是正常迁移。

## 后台与多窗口

- 后台优先，不默认占用用户鼠标、键盘或切换页面。
- 单 CAD 实例控制器与精确 B 文档控制链的前提不同，不能去掉实例数量限制后混用。
- 进程 PID、完整 DWG 路径、文档与范围必须同时匹配；重启 CAD、换图或重新绑定后要重新生成相应输入。
- 精确 B 路线包含已验证的混合 ARC / LINE 功能代码；这不表示所有连接候选、多窗口布局和任意文档都通过了验收。失败时停止对应步骤，不自动转成前台盲点操作。
- 发布包不附作者的会话凭据、状态、图纸、测试板和历史运行记录，也不将它们伪装为新机默认值。

## 能力成熟度

完整批量命令仍为 `VALIDATION_CANDIDATE`，不是跨图纸生产就绪。特殊文字修复的历史“三轮通过”只支持原样本与相应实现，不延伸为整套流程或新环境的通过结论。离线测试和构建检查不证明新机已加载命令，更不代替真实图面验收。

本次发布整理不改变标注算法，不启动 CAD，不操作真实图纸。接收方完成本机安装与适配后，应保留自己的测试证据；不要把来源记录复制成自己的成功记录。
