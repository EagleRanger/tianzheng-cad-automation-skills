# CAD意见综合、批量修改与验收



用于连续审图意见、同类批改和跨图联动。标准化的是意见如何保真、执行和核销，不是让模型重写用户的设计。以下为可试用流程；引用的单项技术有实测依据，整条流程的效率和漏项改进仍需后续自然批次验证。



## 原意见保真，执行动作合并



沿项目已有的唯一MD维护意见，不新建平行任务清单。用户原话、图片/文件及版本、方位、数值、范围、先后顺序、允许误差、保留/取消/例外均保留；归纳只作为导航，不能替换或删掉原文。没有给定的设计值不要为了补齐表格而猜。



用户仍在收集反馈时按其安排记录；明确统一修改后再综合编批。补充/纠正沿原ID记录最新有效后态与替代关系，旧要求标为历史，不同时执行冲突版本，也不把原要求漏落实包装为新需求。



跨对话回传“用户最新意见”时，回传时间不能代替原指令时间。内容已在原ID、与当前阶段冲突或疑似恢复上下文重现时，只定向核原人类消息的来源和时间，区分新指令、重复提醒和历史权限；重复引用沿既有条目继承，不重复派单、扩大已改对象或插换工序。转发给出原来源和真实增量；无上述疑点不额外读历史。



在同一个MD中增加简短执行分组，或在现有机器计划中引用原ID。批次不是第二个要求源，不复制长篇历史。按需要写：



| 批次 | 覆盖原ID | 对象/区域与有效依据 | 统一动作和不得改变项 | 依赖/独立待定 | 对应验收证据 |

|---|---|---|---|---|---|

| 本次大项 | 原意见中的ID，不能自造替代编号 | 完整同类集合；不只列脚本已选子集 | 原后态及最小必要直接联动 | 使用哪份已验输入 | 一份证据可支持多条，逐ID回填 |



执行前做双向对账：每条有效意见都有批次、已验继承或明确的局部待定去向；每个拟改动作都能追到原ID或它的真实直接依赖。一项意见可涉及多步，一次批量可完成多项；每个独立后态仍须核到，不能用“本批完成”掩盖漏项。



例如“换十字、变大、不移位”可以一次处理同类符号，但形状、尺寸、中心保留必须分别验；“删路并补草”可以与邻段同类问题合批，却不能只核删除数量而漏掉旧接口、空带与失效分界。无需为每个后态另出报告或增加审批。



## 编批前锁对象与实现边界



- 按最新有效源、实际修改段、对象角色/拓扑及原生身份判断全集。图层、颜色、块名或关键词只能筛候选；匿名动态块追有效基名，块内对象和外参另核。界外/其他段的同层内容保持，不借整理扩改。

- 分开设计数据、现状实测、几何控制、标准做法和显示样式的依据。一份新绿化图不当然更新全部水工参数；来源旧统计表也不当然是竣工数量。

- 先明确后续实际使用方式：仅背景联动可用项目约定的外参；需要直接分割/修改/逐块引用时按项目要求保留本地原生实体、组/块和依赖。显示存在、外参Resolved不证明模型内可直接编辑。跨图复制核源→目标映射和同名图层/块/线型/文字样式冲突，不盲目Ignore。

- 同时列修改集与保护集；真实缺口只问设计取舍，不询问已授权的常规实现。可以自行选可靠命令/API、编组或块等实现；不能自行增加道路连接、改变折角/岸线角色、填掉水域、替换材料、放宽权界或新增保留例外。



## 按真实依赖执行，按大项回传



通常顺序是：依据及完整对象 → 底板几何/接口/可编辑组织 → 依赖填充分区 → 标注/数量/图例 → 图幅与正式出图。只做本次变化触发的一圈直接依赖，不因改一个索引数字启动全套设计复核。



已验方法在同条件直接批量使用；新方法或关键输入变化才先验证能揭示错误的代表对象。执行端在同一写入宿主中连续做技术自检和同类修正，不每小段等项目端许可；整个可审大项完成后统一回传。项目端按原话和完整对象核验，集中返回失败ID/位置/原因，不重复查未变成功项。



未决点只冻结对应对象及真实依赖，保留现状，不猜答案；其余独立工作继续。一个大项可带明确局部待定返回，已验输入可支持不相关后续。用户暂停时先保存保护并停住，不以旧心跳或剩余待办自行恢复。



本机未验证多宿主生产并发时使用一个CAD宿主串行。同类合批复用已证明的控制链；改完保存或另存，直接在当前宿主/文档连续做，不把保存点或大项完成变成固定重开/关闭任务。仅保存/宿主异常、文件恢复或明确需要核重开效果时按需重开；结束后按既有收口规则处理。当前PID/文档路径/保存状态现场读，不猜旧PID，不强杀未知保存状态的程序。保存、改动后态、区域图面和项目端监督的触发条件统一见[检查频率](annotation-control.md#检查按触发条件执行不按每次微调重复)，不再各加一轮同义核验。

## 多对话交接：管理、执行、校审



仅在项目已设专门对话时使用；多个 Codex 对话不等于多开 CAD。业务范围、暂停、底稿和原意见只取项目唯一清单；本 Skill 不授予写图或对外通信权限。



- **管理**：保留原要求，明确唯一下一责任人，负责授权范围内的统一派单、汇总与人工验收。**执行**：唯一写图，按明确动作实做，完成保存所需的技术自检。**校审**：只读，以同稿原生对象和实际图面判断对错、指向和验收依据；缺证标明缺哪项，不代改图。管理不再做一遍图形校审，执行不重复校审。

- **共享清单直接承接，不转抄任务**。已用唯一 MD 时，原话、截图、原 ID、当前稿、允许范围和应达后态都在原处保留。管理维护要求与工序；执行更新实改、保存和技术证据；校审更新验收结论、证据缺口和真实返修项。用户已授权内部直接返修时，交出方可更新本批下一责任人并直接通知，不等管理重派；不得改授权、阶段、原要求或覆盖其他角色结论。JSON只承载既有运行游标与技术证据，不再维护平行要求清单。

- **一批只通知一次**。接手者直接读共享 MD；跨聊天只发送清单入口、责任人及本批范围的短接续通知，不粘贴已经在清单中的整套要求或旧回执。新通知只在责任转交、整批完成或真实阻碍时发送，普通保存与小项进度不逐条转派。若用户已明确由校审直派，沿同一派单核进展，不补发。

- **未完项必须落到动作，不能止于汇总**。校审能补证的自行补证；有依据的差异在原ID写清后合批直接交唯一执行，跟到实际修改、保存，再核受影响项。执行保存后直接通知校审，不把内部接续退回管理。缺来源只用已有明确资料定向核，确需用户判断时附清楚图示和选项回管理；其余继续。普通“未完成”不是终态，也不是给用户的进度成果。管理只收整项结果、首次真实阻碍或必要用户选择；只在交接断档时补派一次。

- **管理只加载管理信息**。默认读取目标、完成结论、本轮原意见数量和位置、当前责任人及阻碍；对象级证据、图像、原生几何与试改记录留执行/校审。字段太长就给共享原文位置，不把全文重新塞进短摘要；不删减原要求。工具读取先筛选再输出，已完成过程不重复载入。

- **清单收口与图形重审分开**。用户问“之前意见是否全完成”时，由校审对原意见和已有回执集中对账；已过结论复用，缺回执不直接等于未改或绘图错误。仅真实未覆盖且会改变结论的对象补证；不得因为汇总清单、普通保存或管理交接，再开启一轮全图检查。

- **用原生增量确认消费**。沿现有 send_message_to_thread、wait_threads 与游标确认目标和状态，跟到首个与原 ID 相关的动作或明确阻碍。工具送达或口头接单都不算开工。只有空闲、未开工、未报阻碍且仍有可做动作时，才补一次具体接续。原生在途、已直派、已处理的同一范围都不重复唤醒。

- **只送真实的新差异**。清单明确下一责任人为校审并已标待校审，且首次大项或受影响原 ID 有新实改、有效新证据且没有同范围回执，才送既有校审。普通保存、回传、撤图、交付形式变化及无新依据的待核不重审。已通过范围沿用；用现有回执和必要 CAD 局部，避免重复整图、启宿主或出 PDF。



## 检测顺序与完成标准



先核专项规则确实进入当前消费者：定向读完整相关条款，明确其在规划、生成和自检中的实际入口与判据；在已有批次记录保留一次调用及效果依据。不同项目标注轮次读过规则前130行，其中已含“群内与外引分验、不能为零交点制造远抛”，但v258规划仍将GRASS区域及全部地形线作为文字硬障碍，再扩大搜索；这属于规则未消费，不能只归因为漏读后面的N15章节。修改调用路径须同时修实际消费者和反例检查，不能只补一份Skill文档。该案例的图面修复仍须当前项目验证。



开始依赖场景内容的定位/避让或图面检查前，先核**当前实际副本目录**的必需依赖：实际引用路径正确、文件存在且运行态成功解析；换编辑/重开目录须重新满足这些条件。验收既比较前后变化，也比较要求中的合格状态，不能只核两个错误状态相等。不同项目v126/v127均为地形外参FileNotFound而相等，较已验v120/v123的Resolved退化，曾误作外参一致；缺失场景的图不能证明避让通过，块有包络也不证明外参已加载。只撤回依赖该场景的图面结论，保留有效原生对象与无关已验范围，补齐原依赖后核受影响画面。证据为不同项目既有evidence/v120_groundcover_inventory.json、v123_samples_before.json、v126_after_inventory.json、v127_after_inventory.json及项目latest_annotation_sample_display_review/terrain_xref_correction；此记录证明失效条件，修复效果仍须后续实测。



1. **原生与功能**：类型、模型/布局归属、整体编辑语义、组/块成员、直接可引用性、样式/有效颜色。命令返回成功和句柄计数只是执行事实。

2. **范围与保护**：从用户要求独立检查应有/应删全集，核端点、真实XYZ、连通/断开、旧残留、漏填/越界/叠压和直接接口。不能只检生成器自己的选择集。

3. **实际图面**：在当前候选核风险局部，再扫完整受影响段/图幅；包括跨幅接缝及只在模型可见、不打印的残界。图案名/Scale相同仍要核完整图案定义与实际显示。

4. **保存与交付**：保存当前候选并确认实际交付文件及其需要的依赖；常规在当前文档核本次改动和图面，不强制独立重开。只有具体保存/宿主异常、恢复或明确重开效果验证才用临时副本诊断，保护源与冻结交付件。正式出图另核纸面比例/CTB/图签/目录。执行自检、项目端验收、用户接受分别报告。



几何筛查的阴性结论须有读取覆盖依据：区分候选、成功解析、按明确角色排除和失败对象，保留失败句柄/类型/异常；不能以except:pass吞错后报告无交叉。不同项目v136两分支对ezdxf Vec3使用[:2]触发TypeError而跳过当前图和地形曲线，实际8㎡及354㎡标注仍穿线；项目端同运行时复现，显式(x,y)可读取。修后先用已有明确冲突验证能够检出，再核修后实际图面；不把失败当空对象，不为通过改设计线，未知只阻塞对应局部。此为已复现的读取反例，具体批量修复与最终避让尚须实测。



某一层失败只返修它与受影响后续；不把上述顺序变成对每个对象重复启动CAD、截图和审批。既有匿名组按持久句柄及成员核，自动键编号、REGION标识、浮点尾差或图形缓存变化需分辨来源，不自动当设计变化；这不替代工程精度要求或实际显示检查。



### 接头留删和区域清理



涉及两组构件交接时，先取当前有效来源，定出“哪一组从哪侧来、在哪个实物接口停、另一侧保留什么”。验收要从保留段向接口走一遍，并核接点另一侧多出的段确已去掉。只证明选中对象删完或两组不再重叠，无法排除删错一侧。接点未判明时只挂起这个接口，不靠固定级数猜。



清理“某区域有多余图例或范围”时，用源图和该区域的实际硬质边界确定范围，不能用执行脚本的选择集当检查范围。区分真实构造、有效种植和误留的识别线/图案，查整块受影响区域及其边缘，不按图层名整删。局部通过只保留为局部证据；旧状态与新纠正冲突时，在原条目旁标清旧证据能证明什么，并撤回受影响的通过结论。在同一大项的一组CAD画面与原生对象中一次核完，不增开宿主或逐点截图。



## 截图与正式出图



常规空间/外观核对优先使用当前CAD的区域放大实际截图；原生API定位视口并重生成，待绘制完成后捕获。一次完整帧可以裁局部/复用，不反复生成同一画面。保留保存稿路径及版本、图签或区域及真实捕获方式，同一幅证据复用，不为截图计算文件哈希，实际看图确认目标，不能只看quality=true。



常规检查的实际调用必须进入截图分支，不只是任务说明写“截图优先”。现有接口把`paper_views`实现成PDF打印时，不能把它当截图字段调用；没有纸空间捕获分支，不等于CAD截图不可用。原生数值、角度和中心可按相应读回检查；标注重叠、压字、串线与邻注关系必须按实际目标布局视口的可见集合及CAD画面判定。模型空间叠着多个图种的对象，不能替代视口碰撞判断；模型捕获只能证明其实际可见内容。缺布局截图入口就只修该入口，不继续依据未经确认的字框碰撞穷举位置，也不改走PDF。不要为截图借用会创建实体或改变业务图层的分支。



- 不占前台时，复用已验证的准确HWND PrintWindow路线；兼容脚本显式 `-Backend PrintWindow`，不默认Auto回退屏幕复制，不激活窗口、不移动焦点、不发鼠标键盘输入。

- 不同项目v111/v112自然批次实测：隔离桌面PrintWindow连续黑图后，完整CAD内`DocumentExtension.CapturePreviewImage`在原生视口定位、Regen/UpdateScreen后取得可核模型图面，置石层开/关呈真实差异且未占前台。相同宿主条件可复用已验原生模型捕获；它不是桌面UI截图，也不证明菜单/选择夹点/正式打印。该历史试验固定了候选SHA及临时副本；日常复用捕获方法只需绑定当前Document和保存稿，记录设置后实际视口及输出尺寸，按完整受影响包围范围检截图覆盖，不只数张数或复用旧中心列表。仅项目v111/v112这种已验调用条件成立，其他宿主需核实际效果；黑图时不继续重复PrintWindow或改走前台。本包已有 `../../tianzheng-batch-polyline-dimension/runtime/src/CodexCadDocumentPreviewCaptureV1.cs` 提供同类模型捕获实现；不是对历史专用命令的复刻，也不保证新宿主的天正对象显示。

## 问题分析与修复



此链用于发现异常、收到纠正和问题复发，不是每改一个夹点都重新填写的检查表。复用项目原ID、现有修改记录与实际证据，不另建问题台账；执行完成可审大项后集中验收，局部未知不阻塞独立工作。



1. **发现并判定问题**：把当前图号/对象、要求中的目标后态与实际现象对应起来，先区分真错误、按图允许的表达和未知。按图种从当前有效措施核应注内容，再对旧注；旧标注存在不代表现在仍应标，普通淡显底图穿过文字也不自动构成冲突。复用已有原生读回、CAD截图及已核范围，不先扩大为全图搜索。

2. **分析失败层次**：定向核来源版本/权限 → 当前措施和对象角色 → 内容、数值及指向 → 原生操作/拓扑 → 图面排布 → 显示或保存链。前层无效先解决前层；不能用美化无实物旧注、改测点腾文字、重建对象掩盖捕获失败。事实、推断和待核分开；距离、同色、同层、同句柄及包围框只支持定位，不能单独证明措施身份或取消。

3. **调用已有经验解决**：先定位本类型已验实现与同类反例，区分经验缺失、规则过期、未调用、实际未执行和执行后效果不符。修改造成失败的当前条件/规划/消费者/判据，不只追加“下次注意”。措施取消则清失效表达，移位则跟同一实物迁移/重建清旧，新增必要表达则补；有效对象才进入就近排版。输入、规则和方法均未改变时不重试同一失败方案。

4. **核实际结果**：针对原异常及真实直接依赖，确认它已消失且语义、数值和受保护对象仍正确；常规保存后在当前CAD文档看实际受影响区域。已知反例应能被修后的实际判据拦住，但不要求每轮另造测试文件/宿主、全库导出、例行重开或PDF。项目端与执行端采用同一有效判据，不能执行排除背景而验收又因普通背景返修。命令成功和技术计数只证明相应环节，不能替代原要求完成。

5. **沿原入口沉淀并再用**：项目原话、实际对象和结论留原MD；可复用机制写回相关类型Skill/共用规则，并替换冲突旧条款。保留问题、已验证原因、修正位置、适用条件与未证部分的短证据指针。新条件或同类复发时只读相关增量；核实际批次是否采用及原问题是否再现，不以条款增加、路径可达或宣称“已读”表示已生效。同一原ID返修次数和同口径实际耗时可复用现有记录判断改善，不另设日报/指标系统。



不同项目本次两类反例分开处理：已验证样例早已允许覆盖普通地形背景，不同项目仍将其当硬障碍，属实际规划/验收未采用已有经验；修的是角色和判据。另有原坐凳随已确认取消平台消失，清理对应旧索引的依据来自原措施与取消记录、现行图面，不来自“附近没有某类Region”；修的是措施—标注关系及其失效表达。两例的本图句柄、色号、尺寸和取消范围不能移入别的工程，其他未知构件也不因此自动删除。



同类后续纠正还包括重叠分幅的坐标：用户确认同一组只需一个视口完整显示，相邻重叠幅裁切不必修。此时应撤销与当前表达要求不符的“每幅必须完整”判据，保留合格旧注，不继续搜索位置；仅限已确认类型和场景，不自动改掉乔木/地被等另有约定的跨幅规则。发现问题也包括识别“原来判错了”，不是所有截图差异都需要改图。
