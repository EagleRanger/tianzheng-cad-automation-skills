# CAD运行组件与模型接续

仅在恢复接口、换模型接续、模块扩展或移机部署时读取；普通改图仍调用当前项目已接好的入口，不额外启动架构检查。

将**能力接口、机器环境、项目业务、运行实例**分开维护：

- 能力接口声明输入、真实副作用、后态回执及适用边界。已验原生操作继续复用，不为新模型重建控制链；缺能力只扩对应模块。
- 机器环境提供 CAD／天正版本、安装路径、COM标识和捕获依赖。移机检查依赖后，在目标电脑隔离实测加载、保存和实际图面；仅路径存在或编译成功不证明兼容。
- 项目业务继续由原唯一清单决定来源、允许对象、工序与验收；旧句柄或同名块不能跨稿移植，接口成功也不能证明选对工程源。
- 运行实例绑定真实PID及创建时间、实际文档、保存点和未决请求。换模型读取同一实例，不重启、不重发已消费请求；候选模块不热替换在途宿主。

具体操作也沿此边界落地：来源与范围、对象／图幅定位、参数规划、校验、一次提交、原生执行与保存、回执结算、实际图面、业务验收分别有明确负责模块和输入输出。先查现有模块，已实现的直接调用；新增能力只扩对应接口并验证真实消费者，不把机器探测、工程修改、截图和验收核销重新拼进一段临时脚本。项目参数可临时生成，通用控制逻辑不随每批重写。模块可以是具有独立合同的已有函数，不按文件数量评价模块化；同类动作仍可合批，保存仍在原生事务中完成，不增加逐步骤聊天、审批、宿主或截图。

恢复时先核用户要恢复的**内容版本**。需要回到换模前时，以原业务保存回执、可保护备份及对应内容取证，不凭文件修改时间或“当前最新”选稿；无法证明完全相同时说明时间和证据边界。换模后修改另留保护，不能静默混入恢复基线。原要求、当前技术状态和历史副本各用原入口，不抄成多份状态。

可用性分层核验：模块／协议离线通过 → 当前宿主、依赖及实际图幅接通 → 原未完业务的实际修改、保存、改后看图。三层分开报告；图纸完整交付仍按原清单及既有校审。`CapturePreviewImage`预览与当前CAD窗口捕获是不同证据；预览空白时先核实际文档／布局／视图和既有后台捕获，不据此重建图形或切用户前台。

用户明确由管理修接口时，管理先做窄范围技术修复及验证，再交付可执行入口和原未完项；不把编译、宿主重建、请求哈希和截图调试交给绘图执行者。这是该次分工授权，不把所有项目管理角色永久变成CAD写入者。交接跟到实际消费，普通在途无需重复唤醒。

## 本包实现与边界

已验单宿主后台组件位于 [runtime](../runtime/README.md)，统一入口为 `../runtime/cad_session_client.py`，构建与导出入口为 `../runtime/cad_components.py`。源码、协议、控制链、分项原生模块与离线测试一起提供，不依赖作者的项目目录、聊天或已有 DLL。

先读组件说明和能力边界，再在接收方已有合法 CAD/天正环境探测依赖、编译和绑定自己的工作副本。现有成熟运行链不因换模型重启。后台多宿主并行尚未验收，本包不提供其研发候选。

跨图纸空间根对象复制仍有显示验收限制；窄范围引出复制不能自动等于保色或全图显示合格。专项范围以包内能力说明及接收方实测为准。
