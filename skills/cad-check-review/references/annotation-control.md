# CAD标注的类型路由与闭环控制

适用于同一用户的CAD标注生成、修改、连续纠正和整类核验。项目原话和对象全集仍在项目唯一清单；本文件只维护共用控制方法。沿当前唯一写入者、隔离副本和后台接口执行，不启动旧项目任务。

## 先定类型，再调方法

| 业务对象 | 入口 | 必须区别的内容 |
|---|---|---|
| 乔木组名称数量、串线、自由外引 | `../../cad-tree-group-annotation/SKILL.md` | 成员串线与自由外引分开；图例中心、首尾连接先于排版 |
| 灌木/草本/地被/水生/草坪名称面积 | `../../tianzheng-groundcover-annotation/SKILL.md` | 真实有效分区与整体原生引出，不套树组首尾 |
| 坐标定位 | `../../tianzheng-coordinate-annotation/SKILL.md` | 真实测点/轴序数值与显示位置分开，图种决定密度 |
| 标高/坡向 | `../../tianzheng-elevation-annotation/SKILL.md` | 高程值、符号和文字联动，不当成坐标或普通文字 |
| 构造/详图/剖切/多落点索引 | `../../tianzheng-index-annotation/SKILL.md` | 实际构件、正文、详图引用、完整拓扑分别核 |
| 线性宽长、圆心角、半径/直径 | `../../cad-dimension-annotation/SKILL.md` | 真实源段与测量语义先于外带排布，不套普通植物引线 |

这些相对路径从本reference目录出发；读取时先定位本包或接收方安装目录 `skills/` 下的同名目录。命令名、层名和夹点数量不是原生类型证据；以当前RXCLASS、属性、显示组件及来源几何确认。静态接口研究仅是线索，不能覆盖后续实机反例。

## 一条短控制链

1. **要求**：读当前唯一清单的本批ID、最新纠正和替代关系。区分用户明确要求、项目参数、可复用规则与尚未验证的方法。仅合并执行动作，不压缩原话、例外和独立后态。
2. **快照**：准确绑定当前输入和宿主；读取本批原生类型、属性、实际夹点/显示子件、来源、图种及真实可见范围。基线加已核修改集构成当前状态；仅失效变动对象及其依赖，不因一次局部另存导致DWG哈希变化就重新抽取全部地形、HATCH和未变图块。无法可靠追踪的部分重新读取，不能拿过期缓存冒充现状。原件、有效底板和用户手改保护。
3. **语义**：先按当前图种与已确认的新底板核实际应注的措施/测点/源段，再与旧标注对应；不能只把旧标注全集当作待美化对象。仍有效且本图需要的保留或必要调整，措施已取消的清失效注，同一措施移位的迁移原生标注或在新位置重建并清旧，新增必要对象补注。已核对应关系复用，未知只挂单项，不另造全图库存；同句柄、距离近或原文字相同均不能单独证明当前实物仍有效，不为旧注改指最近另一措施。之后才核本类型成员/中心/首尾、有效种植区、坐标轴序、标高值、索引源构件或尺寸源弧，合格对象方可进入排版。不能用树冠内代替中心，不能用同组线内代替组端，也不能用包围框相交猜对象身份。
   - **无源标注先筛出，不进入排版**：对本批受影响标注a，只从当前仍有效、用途与a相符的工程措施集合F中找支持，普通地形/网格、GRASS纹样及另一近邻构件均不算。令`S(a)={f∈F | 同一措施或有据的新旧对应 ∧ 本类型几何关系成立}`。`S(a)`为空或用途/对应未知时，直接输出“待删除／待改（缺有效措施支持）”，不能默认保留后继续美化；已经由用户/本轮有效取消清单确认的同一措施进入删除集，同一措施已移位则进入更新集。仅邻近无物不授权自动物理删除；控制基点/轴线交点等有明确定位用途的坐标可由其真实控制关系支持。
   - 几何初筛从原生真实测点/尺寸端点取值，先统一空间：坐标核`min‖p-c‖≤ε`，c为该措施已确认控制点；线性尺寸核两个测量端点分别与**同一有效源段/断面**的对应端点相符；R/角度核相同源弧/中心/边，说明/索引核真实指向与同一构件。ε只取本图原生拾取/变换精度的有据容差，不写跨项目固定搜索半径；不把“附近任意曲线的最近距离小”当作身份正确。筛选使用已取得的本次改动及相关原生几何，不另做全图反复导出或依赖截图OCR。保留/更新/删除/待核结果应在本批实际消费者中先于避碰与审美执行；规则已写或附近有线不等于源资格通过。
4. **规划**：从合格语义输入产生附近候选，再按实际同幅可见对象分级避让。有水平文字承托线的引出先按下节90°优先，不默认搜索45°或多角度。成员串线、自由外引、文字、符号、主要构筑物和软背景分角色；不把整个XREF框或一层全部对象当硬障碍。必要时只联动已授权邻注；不扩大搜索、改变实物或生成无用途折点来求零交点。某对象无解只挂该对象。
5. **原生执行**：一份数据化批次传入已验证控制入口。同类多对象用数组/循环执行，逐对象读回并记录实际成功、未执行及失败；失败不能吞掉或回报整批成功。属性先设，按已证拓扑逐次移动并重读夹点。规划目标不等于实际后态；控制器不另算一套坐标或猜文字镜像。
6. **实际自检**：对实际原生读回再次检查语义、数值、拓扑和保护项；依实际显示子件重算碰撞和受影响视口。不能只审输入计划，不能以两次同样错误的读回一致证明布局正确。只将失败差异返回规划，输入/障碍/规则无变化时不重试同一方案。
7. **整项验收**：同类大项完成后保存当前工作稿，用该保存点对应的原生后态和当前CAD实际图面核本次完整受影响范围；常规不另开副本或宿主。项目端独立验收指职责独立，不等于必须重开CAD。项目端按原意见逐ID统一核，集中返修；不逐组制造批准点。真正影响方法适用性的新条件，可先验证一个代表对象。保存成功、截图生成、局部通过与整项通过分开。

## 有水平文字承托线的引出：90°优先

用户已确认的默认排布顺序（2026-11-03）：适用于坐标、索引、一般说明和灌草地被的单源外引，不套尺寸/角度/半径、标高符号和乔木内部串线；多落点对象保持原生分支，不合并锚点或强套三夹点。

最终允许三种模式，角度按实际纸面引出方向区分：**90°竖直引出为默认；0°水平直引和45°斜引按当地空间选用。** 旧斜引出外观规则保留并后置，只在采用斜引模式后检查，不能据此否定可读的90°或0°。这里45°指斜段方向，其与横向承托的折点仍应为90°或钝角；0°是同向水平直线，没有需要强造的折点，不把它当作180°退化折线，也不允许折返回头、零长线或用短弯伪装。

1. 固定实际指向P，在实际纸面坐标先竖直向上引到折点E，再用水平承托线到T，文字向左或右展开。若P=(x,y)，则E=(x,y+h)、T=(x+s*w,y+h)，h、w>0、s为±1。按本图字高/现有模板取长度，不写跨项目固定距离；旋转视口先变换到纸面再算，最后准确映回原空间。
2. 有压字/压线时，先在上侧调整引线长度、文字左/右侧与整组位置，保持实际90°；为离开坡顶线/粗虚线可适当加长，不以最短为唯一目标。上侧没有合适空间可向下；当地左右空位适合时可选0°水平直引，斜引外观及搜索后置到90°之后。0°与45°按就近清楚及实际空间选，不机械试完全部组合。不先穷举斜率、机械远抛或给引线添多余折点。
3. 先记录实际模式再检查：90°/45°折线读回真实接头两侧线段，核两射线内角及纸面方向，不用方向角、补角或新增短弯冒充90°。优先调用[check_leader_angle.py](../../tianzheng-coordinate-annotation/scripts/check_leader_angle.py)的`check_leader_joint(leader_segment, bearing_segment)`：输入实际引线邻段和朝向文字/索引圈的承托邻段，函数由唯一公共端点识别折点，线段端点顺序可颠倒；不相接、在横线中段相交或退化不能通过。已验证P/E/T角色的简单对象仍可调用`check_leader_angle`；未知夹点角色先定向核原生拓扑，不按前三夹点通用套算，也不从文字框猜方向。0°模式单独核实际显示线水平、非零且同向，不送入折线180°拒绝分支；同文件`check_horizontal_leader`提供这项检查。三种模式都须核文字/圈/符号避让、有效指向、跨幅和保存，不能凭角度通过。
4. 新建或确需调整的对象按此生成；未改且已验合格的斜引不为统一外观重排。首次在当前图纸用正在修的代表对象自然实测，保留原生实际结果和CAD截图；记实际消费者及正交/有据回退，不把更新文档或候选公式说成实测通过。无需另建测试宿主或重复全图检查。

**同一判据必须覆盖实际类型。** 折点E、引线侧相邻点L、朝文字/圈的承托侧相邻点T，取`u=L-E`、`v=T-E`，`d=(u·v)/(|u||v|)`；`d>0`为锐角，`d=0`为90°，`d<0`为钝角或180°退化，后者另拒。仅容浮点舍入，不取绝对值、不取补角、不把承托射线反向延长。长引线有实际中间转折时用E的相邻段，不用远处测点替代。索引、坐标、说明/地被外引分别接入同一判据；某类坐标通过，不能替代本批索引或其它外引的角度结果。复合对象按真实接头逐分支核；本批新建/调整的适用对象若缺角度结果或拓扑未定，只能待核，不能随文字/图号正确而通过。用已有原生读回就地计算，不另启宿主、不为算角出PDF。截图核排布与显示，不承担数值夹角判定。

## 检查按触发条件执行，不按每次微调重复

这里的“大项”取项目已确定的完整可审范围（例如本轮全部乔木标注），不能把一两组改名为大项来重复收口。合批包含当前方法下条件成熟的同类对象；局部未知单列，不等到所有疑点解决才执行。要求/方法未变时沿现有指针读增量，不逐回合重读完整清单、历史和全部Skill。

| 动作 | 何时执行 | 删除的重复动作 |
|---|---|---|
| 方法与原生样本核对 | 新实现、真实适用条件变化或反例出现时；未变复用 | 每组重复模板试验与同一反例测试 |
| 编译、宿主和模块初始化 | 实现改变才编译；同类数组job共用一次已验证生命周期 | 仅改句柄/位置/输出名就复制源码、编译并冷启动 |
| 保存与范围保护 | 每次实际修改完成后保存当前工作稿，确认目标路径及保存结果；保留原件和已有有效恢复稿。仅核本次对象及直接联动，真实异常再定向展开 | 例行每批前后全图Inventory/DXF逐实体比较；以尚无修改集追踪为由强制全量导出；反复生成全组/表或重复快照 |
| 原生后态 | 每个实际修改对象及其直接联动邻注读回类型、数值、中心/夹点和修改范围；同份结果供后续复用 | 将已读原生结果为不同报告重新采集 |
| 区域图面 | 当前合批受影响范围去重后检查；已有完整帧可裁取，返修只重看变化及接缝 | 每标签固定若干整幅PDF、重复转换和同帧重复捕获 |
| 保存后继续 | 修改完成保存或另存，核实际保存路径/结果，复用当前宿主和文档继续下一项 | 保存后例行关闭再开；每批或大项末固定重开 |
| 按需重开 | 保存/宿主异常、文件恢复、或任务明确要核重新打开后的效果；写明具体需要证明的问题 | 把“完整大项完成”“独立验收”本身当重开理由 |
| 项目端进度监督 | 紧凑原生状态与新证据指针；大项完成统一按原ID验收。新错误/真实取舍仅核影响局部 | 每次回传即重哈希候选、全量比较、复制整份回执并设放行点 |

数组job、准确身份绑定和安全保存方法一起复用；常规留在当前文档接续，不让每批finally关闭/退出后再冷启动。另存后绑定实际保存路径，避免后续仍写旧路径。既有一次性关闭逻辑只用于明确结束、用户要求或异常处置，不直接套到连续工作；已验证样例`../tianzheng-batch-polyline-dimension/runtime/src/NativeAnnotationJob.cs`的`native_clones/native_updates/native_positions`是已测数据与控制分离例子，不能重放其旧业务job或套错原生类型。若后台只能一次启动执行一个任务，就合并该次任务的记录，不临时造未验证常驻服务。

检查边界跟随用户要求：确认本次要求的完整后态，未修改且未受影响的内容不复查；不能把“直接邻区”自动扩大为周边所有对象。只有实际联动、新或未验证方法可能造成范围外影响、真实异常时，才按具体影响扩大检查；大项统一验收亦仅覆盖本次要求及真实受影响范围，不默认重验整张图。规划、最终输入、实际后态是不同校验层，实际读回限本次对象和直接影响；确定性规则使用同一函数和同份有效数据，变更后才重算。先用已有数据筛候选，不靠反复真机试摆；实际显示子件不能由旧字框平移/镜像冒充。常规全量导出/比较默认关闭，不转移成大项结束时必做的全库检查。发现实际越界修改或保存异常，再沿证据定位影响范围；大项仍按原意见核实际图面，不能把“保存成功”称为质量验收。

常规显示使用已验证CAD区域捕获；实际job须走截图分支，不能将实现为打印的`paper_views`当作截图。数值、角度、中心按原生证据检查；重叠、压字与排布按对应布局视口的实际可见集合和CAD截图判断，模型空间不能代替。布局捕获缺口只处理对应入口，不能仅因接口不支持而自动打印。PDF限明确输出或具体打印属性问题，限定范围、结束即退回截图；不借曾经的打印诊断延续日常出PDF。具体入口及失败处理见[截图与正式出图](drawing-change-workflow.md#截图与正式出图)。

已有审美规则的执行顺序：先确定实际目标视口及可见对象，再按角色区分真实文字/重要工程与普通细底线，然后按已定就近、换侧、错层规则选可用方案。包围框或圆冠范围相交只是候选提示，不自动等于实际字形碰撞。筛查无法分辨而截图入口又缺失时，停止对此对象继续扩大角度/位置搜索，先补齐这一个可见性缺口；其它条件成熟的同类对象照常合批。无新输入不重算已有无解结果，不用新增约束、更多过程版本代替成图。执行端完成大项后项目端集中检查，过程中只介入真实规则误用、越界或方法失效，不恢复逐点审批。

身份、来源数量、真实锚点/中心、依赖实际Resolved、修改范围、异常保护和最终图面验收均保留。一次记录当前消费者/规则版本，代码或规则改变才刷新；源文件不被重开改写的保护仍按现有生命周期执行。项目端只记录结论和证据指针，执行详单留既有执行记录，不在多个JSON重复复制。

## 用户纠正如何沉淀

每次新意见沿以下顺序更新已有入口，不另建意见库：

1. 在项目唯一MD保留原话、图片/消息来源、对象范围、优先级和替代关系；先决定该意见属于哪类标注。只问真正未知且影响该局部的内容，已答复不重复问。
2. 项目特定的品种、数量、图号、轴序、字高、比例、每幅密度和具体阈值留在项目；适用的操作原则写入对应类型Skill。跨类型控制漏洞更新本文件，避免向每个Skill复制一遍长规则。
3. 更新原规则所在小节，旧相冲条款标明已被替代，不只在文件末尾追加一句。执行者读当前有效小节，不靠长上下文摘要、固定前N行或旧回执恢复规则。
4. 将规则落到**实际规划、原生生成和原生后态自检**。用本次真实错误验证“旧错会拒、合格表达不误拒”；已有覆盖未失效时复用，不逐对象重复测试。
5. 执行端回传当前消费者与候选，项目端核方法调用和成品效果。只有规则文件修改或离线测试通过时，明确说仍未证明真机/全图。根因未核清不归罪模型、上下文或用户表达；候选方法未在独立场景复用不称普遍验证。
